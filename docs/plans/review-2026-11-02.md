## A. Code quality and correctness of M1–M4

Done well: no key, token or account identity reaches a tool result or `leases.json` (asserted by tests); `LeaseBook.Claim` checks and claims under one lock, releases are idempotent, file writes are atomic; `RefreshGate` and `NetworkBackoff` are minimal and sound; `FreeModels`/`Zones` handle DST with real zone rules; identifiers and comments follow the house style.

Ranked:

1. **Confirmed, data bug.** Lease counters are lost after a restart in any zone west of UTC. `src/Leases.cs:226` saves `Observation.Day` as `yyyy-MM-dd`; `src/Leases.cs:187` reloads it with `Json.FromIso` (`src/Model.cs:314-320`), which assumes UTC and converts to local time, so "2026-11-02" becomes 1 November in UTC-5 and `Today()` (`Leases.cs:127`) never finds today's row. The `LeasePersistence` test passes only at UTC+1. Same mistake makes `checked_at` show the previous day in `src/ProviderDefined.cs:451,473`. Fix: `ParseExact("yyyy-MM-dd")`, reuse `FreeModels.Day` (`src/FreeModels.cs:212`). Small.
2. **Confirmed, cost.** `list_candidates` runs `Candidates.ScanRuntimes` twice per call (`src/McpServer.cs:289` and `:293`); each scan reads every agent auth file and probes about 30 paths over `\\wsl.localhost` per agent. Scan once into a local. Small.
3. **Confirmed, docs.** `docs/MCP.md:7` and `README.md:79` still call the server read-only while the three lease tools write `leases.json`. Small.
4. Lease expiry and backoff compare local wall-clock `DateTime.Now` (`src/Leases.cs:49,101,109,144,231`); a DST fall-back extends a lease by an hour. Keep lease times in UTC. Small.
5. Dispatch PATH for WSL may not contain `node` when npm's prefix is `~/.npm-global` and node comes from nvm (`src/Dispatch.cs:71,80,143-148`). Plausible. See B.2.
6. Dead code: `KeyFinder.FindAll` (`src/KeyFinder.cs:62-70`) has no caller; `Found.Wsl` is read only by a test.
7. Duplicated helpers: `LeaseBook.Items` = `DefinedProvider.Items` (belongs in `Json`); `Dispatch.Version` re-implements `Candidates.DistributionRoot`; `Dispatch.OpenCodeExe` ignores the `access.Program` already resolved; `Candidates.RuntimeKey` repeats the env loop of `DefinedProvider.Token`; `HasCatalogue` duplicates `SettingsWindow.Services.cs:117`.
8. Organisation: two consecutive `<summary>` blocks at `src/Candidates.cs:217-221`; `McpServer.Delegation` is one 60-line method switching on the tool name; `string[][]` rows indexed `v[0]/v[1]/v[2]` and `Tuple.Item1/2/3` where a small record would read.
9. Minor contract gaps: service matched case-sensitively in `Delegation` (`McpServer.cs:610`) but not in `list_candidates` (`:253`); `release_capacity` accepts negative counts (`:597-599`); `Today()` writes `leases.json` from a read tool via `Expire→Save`.
10. Tests missing for: `Dispatch.Version`, `Dispatch.OpenCodeExe`, `claim_capacity` refused by `exhausted`/`rate_limited`, `release_capacity` with `retry_after_seconds` through MCP, lease persistence across time zones.

Verdict: fix 1, 2, 3 (and 4), drop the dead code, fold the duplicates, then good to release.

## B. Does delegation work with any installed agent?

Live on the test PC (fixture path through `McpServer.Handle`, no GUI): `ScanRuntimes` found `pi@wsl`, `opencode@windows`, `opencode@wsl`; `describe_dispatch` returned correct argument lists for all three. Codex 0.163.0, Claude Code 2.1.316 and Antigravity CLI are installed in WSL and were **not reported**.

| Point | Verdict |
| --- | --- |
| Agent coverage | GAP: agents are a C# array of three (`src/Candidates.cs:119-124`); dispatch covers Pi and OpenCode only (`src/Dispatch.cs:22-33,53-56`). An installed agent outside the table is silently invisible; nothing is extensible without recompiling, unlike services (`providers/*.json`). |
| Detection Windows/WSL | GAP: npm-default layouts only. nvm (`~/.nvm/versions/node/*/bin`) is not scanned and not in the generated PATH; only `Settings.WslDistro` is scanned (second distro invisible); a Linux user name different from the Windows one hides every WSL agent (`src/Probe.cs:85-95`); OpenCode on Windows outside `%APPDATA%\npm` is described as the bare `opencode.exe` (`src/Dispatch.cs:60,151-160`), which does not exist. |
| Missing agent | OK: clean empty results, no exceptions. Misleading messages in `describe_dispatch` (`src/McpServer.cs:609-615`): "model not in the list" before the first snapshot, "runtime has no key" for an unknown runtime. |
| Free-model BYOK fallback | GAP: one `notes` string on OpenRouter (`src/Dispatch.cs:90-91`), no structured warning, `docs/MCP.md` silent, and `output` does not tell the plugin that Pi's `usage.cost` / OpenCode's `step_finish.cost` reveal a billed request. |

Honest answer: today it works with Pi and OpenCode installed through npm, in one WSL distro whose user name matches Windows. The structural fix is to move the agent table to data (`agents/*.json` embedded plus `%APPDATA%\AIMeter\agents`, like providers), report `runtimes.unsupported` for agents that are installed but not supported, and answer `unknown runtime` explicitly. This should land before M5's plugins depend on the table. Medium.

## D. Is the code ready for the Microsoft Store?

In order: package pipeline, manifest schema, `runFullTrust` + `internetClient`, startup task declaration, 71 logo files, version scheme, `MinVersion 10.0.22000.0`, privacy policy URL reachable and accurate, no self-update. `build.ps1 -NoInstall -Package` cannot produce the MSIX on the test PC (no Windows SDK); the repository has no record of the MSIX ever having been installed. Policy numbers are from Store Policies v7.20 (2026-09-14).

Blockers:

1. **Confirmed.** Startup is enabled before consent: `Settings.InitialiseStartup(firstRun)` at `src/Controller.cs:76` runs before `AskFirstRunConsent()` at `:83`, and the welcome has no startup row (`WelcomeWindow.cs:44-57`). Policy 10.2.8. Fix: a welcome row, applied after the dialog. Small.
2. Identity placeholders reach the Store: `build.ps1:12-14` defaults, and `build.yml:76-80` passes empty `vars.STORE_*` as "unset". Set the three Partner Center values and make the Package step fail when any is empty. Small.
3. MCP relay launch path is bound to the package version (`Program.cs:44-50` → `McpClients.cs:315`, `C:\Program Files\WindowsApps\<name>_<version>_...\AIMeter.exe`): after every Store update, AI apps cannot start AI Meter until the user opens it. No `windows.appExecutionAlias` in the manifest (`build.ps1:177-181`). Fix: add the alias and make `LaunchCommand` return `%LOCALAPPDATA%\Microsoft\WindowsApps\AIMeter.exe` when packaged; verify on an installed package. Medium. This is the "Store relay path" deferred to M6.
4. Claude Desktop and VS Code config writes (`McpClients.cs:55-57,259-271`) land in the package's private AppData when the file does not exist yet, while Settings reports "connected". Fix: `<desktop6:FileSystemWriteVirtualization>disabled</desktop6:FileSystemWriteVirtualization>` in the manifest (update `docs/STORE.md:41`), or special-case the two clients. Small/medium.
5. **Confirmed.** Six languages declared in `<Resources>` (`build.ps1:168-169`) require six Store listings (policy 10.7). Declare `en-us` only, or prepare six listings. Small.
6. Listing description must open with the dependency disclosure (10.2.4) and the IARC age rating must be filled (11.11.1); neither is in `docs/STORE.md`. Docs.

Nice-to-haves: `Settings.Save` cross-store `File.Replace` on upgraded PCs (verify live); "Open data folder" buttons point at the real `%APPDATA%` path; `runFullTrust` justification should also name `wsl.exe`, `agy`, `cmd.exe` sign-in, Cursor/Antigravity/Copilot sign-ins, config-file edits and the relay script; bundled third-party logos vs policy 11.2; a test seam for `IsPackaged` and a `tests/run.ps1` pass with `/define:MSIX`; document "disconnect AI apps before uninstalling"; the taskbar child-window technique under 10.2.8 is a judgement call.

Store assets: usable screenshots are the four 2560x2000 images in `docs/media` (`consumption-*`, `history-*`); the others are too narrow or too short. A 300x300 icon is one `New-RingPng 300` call in `build.ps1`.

Verdict: not as the tree stands. Set the `STORE_*` variables, add the execution alias, decide on write virtualisation, move startup behind the welcome dialog, trim `<Resources>`, write the listing text and age rating, then install the MSIX once (private-audience flight or `Add-AppxPackage -Register bin\msix\AppxManifest.xml` in Developer Mode) and walk the relay, Settings → AI apps and an upgrade over an existing `%APPDATA%\AIMeter`.
